## 2. 真合約(實讀 workflow JSON,唔靠 ADR 轉述)

### 2.1 2004 `POST /webhook/wf4-sn-update`(header `x-uop-secret`)

Body `{ ritmId, mode: 0|1, notes? }`:

| mode | patch | 語意 |
|---|---|---|
| `0` | `{ state: '3', close_notes: notes }` | Closed Complete |
| `1` | `{ state: '2', work_notes: notes }` | Work in Progress |

`Build Response` 出 `{ status: 'success'|'error', mode, httpStatus, ritmNumber, ritmId, newState, details }`。

sticky 自己寫死立場:**「RITM ONLY. 3 fields: state, work_notes, close_notes. No stage, no tasks, no REQ — deliberate」**。

### 2.2 🔴 三處同 ADR-0017 D3 轉述對唔上(實讀先發現)

| # | ADR D3 講 | workflow 真係 | 影響 |
|---|---|---|---|
| **1** | `addWorkNote(sysId, note)` → **2004 mode 1** | mode 1 **一定** `state:'2'` | 🔴 **最嚴重** —— 見下 |
| **2** | notes 就係我哋送嘅字 | 唔含 `generated by n8n` 就**自動 append** `'Handled & generated by n8n.'`;另外 control char → space、**截 3900 字** | 兩條路徑寫入 SN 嘅**文字必然唔同** |
| **3** | notes 必填 | **optional**,各 mode 有 default 文案 | 平台一律自己給,唔靠 default |

#### 🔴 落差 #1 —— `addWorkNote` 喺 2004 **根本冇對應 mode**

平台今日(`assign.service.ts:306`)assign 成功之後叫 `snow.addWorkNote()` —— **只加一條 work note,唔掂 state**。

而 2004 **冇一個 mode 係「只加 note 唔改 state」**。照 ADR D3 個表 map 落 mode 1 會變成:

```
direct 路徑：assign 成功 → RITM 加 note，state 不變
n8n    路徑：assign 成功 → RITM 加 note + state 改成 2 (Work in Progress)
```

**兩個問題**:

1. **違反 D0** —— 切一個掣就靜靜改變咗平台對外做嘅事。呢個正正係 D0 要防嘅嘢。
2. **語意仲要係相反嘅** —— assign **成功咗**,而張單被標成「Work in Progress」。

⇒ **§8 OQ-A**,本 phase 最重要一個決定。

### 2.3 1007 分工邊界(實讀確認)

### ⚠️ 拍板後揪到一個事實更正 + 一個衍生設計問題

**① ADR-0016 預算 gate 唔係「未實作」—— W36 已經完成。** OQ-E 選項描述當時寫錯咗。呢個唔影響拍板(揀嘅係選項 1),但**影響 F4**:`markInProgress` 真係有嘢接得落去(`assign.service` 個 budget gate 已經喺度,`budgetOverride` audit metadata 就係佢)。

**② 🔴 衍生問題 —— WIP trigger 會唔會 spam SN?**

預算 gate 擋 = throw 400。而操作員可以**不斷重試**同一個 line item ⇒ 每擋一次就 PATCH 一次真單。

呢個喺 F4 展開時必須解,唔可以照 `if (blocked) markInProgress()` 落去。方向(F4 定案,唔喺 kickoff 猜):只喺**狀態轉變**時寫(該 RITM 未曾標過 WIP),而唔係每次被擋都寫。

同樣道理套喺 `closeComplete`:**同一張 RITM 只可以 close 一次**,重複 close 要喺平台側擋住,唔可以靠 SN 容忍。

### OQ-E —— 邊個 code path 有權叫 `closeComplete` / `markInProgress`?(**scope 問題**)

ADR D3 定義咗兩個方法,但**冇講邊個叫佢哋**。今日 assign 成功只加 note。三個候選:

1. 一張 RITM 嘅**全部** line item 都 assign 完 → `closeComplete`
2. ADR-0016 預算 gate 擋咗 → `markInProgress`(「採購中」,D3 明文提過)
3. **本 phase 只做 provider + 介面,唔接任何 trigger**(即 close/WIP 暫時零 caller)

⚠️ 選 1 或 2 = **真嘅新對外行為**(R2);選 3 = 辛只交付「能力」唔交付「行為」,rollout 表個「RITM 狀態正確,無雙重 close」驗收標準**做唔到**。
