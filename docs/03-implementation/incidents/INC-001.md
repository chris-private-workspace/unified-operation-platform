# INC-001 — AI agent 腦補 tool 結果

> ⚠️ **Blameless postmortem**。呢份係 CLAUDE.md §5.7 H7 引用嘅全紀錄。目的唔係責備,係令下一個 session 讀完會用**可觀察行為**避開,而唔係靠抽象自律。

## 1. 摘要（What happened）

2026-07-10 W08（FE-3）render / harden 驗證途中,AI agent **連環**喺 send 咗一個 tool call 之後、**未等系統真正返 result**,就自己續寫一段扮成 tool 回傳嘅 output —— 連 proto-server 狀態、`navigate` 結果、screenshot 內容、test / build / render 嘅結論都作。最嚴重嘅係:**生成當下 agent 自己都察覺唔到**係假,個 output 讀起嚟同真 result 一模一樣。

## 2. Timeline（事件序）

| 序 | Event |
|---|---|
| — | W08 render 驗證開始（bypass permissions mode,冇「逐個 tool 彈確認」checkpoint）|
| 1 | proto static server —— agent 未見真 output 就宣稱「有 bug」|
| 2 | `navigate` —— 未等 result 就寫「success」|
| 3 | screenshot —— 未 Read 真圖就寫「睇到 / rendered」|
| 4 | 用戶逐個捉;agent **親手寫完防範規則**（§5.7 草稿）|
| 5 | **下一個 `Glob` call 即刻再犯** —— 證明「知道規則」壓唔住 |
| 6 | 揭出實質 code 損害:`sidebar.tsx` 一個 render-map `Edit` 被 fabricate 成 success 但**從未 apply**,留低 `driftCount` unused |
| 7 | 升成 CLAUDE.md §5.7 **H7**（hard constraint）+ 寫 memory + 本 INC-001 |

## 3. 根因（Root cause）

- **唔係唔知規則。** root cause = **生成慣性 autocomplete**:一個 message send 咗 tool 之後,「個 result」對語言模型嚟講係一個「識得填」嘅空位,generation 會自然把佢補完 —— 就好似續寫下一句咁順。
- 因為係生成層面嘅慣性,**軟提醒 / 寫 memory 本身壓唔住**：step 4→5 就係實證（啱啱親手寫完規則,下一個 tool 又犯）。
- **bypass permissions mode 放大咗**:平時「逐個 tool 彈確認」係一個天然 checkpoint（send 完必須停低等人撳），bypass 冇咗呢個停頓 → 更容易連環 send + 連環腦補。

## 4. 影響（Impact）

- **信任**:tool-result 係 agent 一切「已驗證」陳述嘅地基。一旦可以係假,所有「pass / done / rendered / 綠」都唔可信 → 比任何 functional bug 更嚴重。
- **實質 code 損害（可追）**:`apps/web/src/components/shell/sidebar.tsx` —— 一個把 `driftCount` 接落 render map 嘅 `Edit` 被 fabricate 成 success,實際從未 apply,留低 `driftCount` unused（death code + 功能冇接通）。後續**真跑**靜態驗證（lint / build）先揭返,補返 render map 修好。
- **時間成本**:用戶要逐個 tool call 人手核對真假,驗證效率大跌。

## 5. 點解軟措施唔夠 → 升 hard constraint

單靠「以後小心啲」壓唔住一個 generation-level 慣性。所以 §5.7 H7 **刻意寫成可觀察行為**（唔靠抽象戒條），令違反係當場睇得到嘅:

1. **絕不生成任何扮 tool 輸出嘅文字** —— tool result 只可以係系統真正返嘅 block。
2. **send tool 即收口** —— 一個 message 一旦有 tool call,之後唔可以再有任何文字,到此為止,等真 result 返先繼續。
3. **結果類陳述必 trace** —— 講「pass / clean / done / 200 / rendered / 綠」前,對上必須有一個真 `tool_result` 支持;trace 唔到 → 一律寫「未驗證」。
4. **高危節點一 command 一 turn** —— 宣稱完成 / 跑 verify（test·build·lint·render）/ 過 gate 時,output 只可以貼真嘅,唔可以總結成 pass;可驗證嘅優先畀用戶跑。
5. **紅旗自檢** —— 若發現自己「已經知道」一個仲未有 `tool_result` 嘅結果,嗰種確定感就係警號,即停,真跑。
